# Keylight

공개 활동 패턴상 초보자로 추정되는 GitHub 개인 계정의 **공개 저장소**에서 AI API 자격 증명으로 보이는 패턴을 찾아, 소유자에게 알리는 작업을 정리하는 로컬 전용 웹 도구입니다.

Keylight는 발견한 키 원문을 DB·로그·브라우저에 저장하거나 표시하지 않습니다. 탐지 즉시 로컬 HMAC 지문과 끝 4자리만 만들고 원문은 버립니다. 키가 실제로 작동하는지 공급자 API에 요청하는 기능도 없습니다.

## 실행

Python 3.11 이상만 있으면 별도 패키지 설치 없이 실행됩니다.

```powershell
$token = Read-Host "GitHub token" -AsSecureString
$env:GITHUB_TOKEN = [System.Net.NetworkCredential]::new("", $token).Password
Remove-Variable token
python app.py
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다. 개발 서버는 기본적으로 `127.0.0.1`에만 바인딩됩니다.

로컬 실행에서는 GitHub 토큰을 환경변수에서 읽고, 서버 배포에서는 Docker secret 파일로 읽습니다. 공개 저장소 조회용으로 **쓰기 권한, 비공개 저장소 권한, 조직 권한이 없는 최소 권한 토큰**을 사용하세요. `.env`에 실제 토큰을 넣어 커밋하지 마세요.

## 개인 서버 운영

장기 실행은 표준 라이브러리 개발 서버 대신 Gunicorn, Caddy HTTPS, 관리자 인증, Docker secret, 영구 볼륨을 사용하는 Compose 구성을 제공합니다. Docker 배포는 기본적으로 15분마다 자동 검사를 시작하며, 이미 검사한 계정은 다시 검사하지 않습니다.

배포 및 secret 생성 절차는 [DEPLOYMENT.md](DEPLOYMENT.md)를 따르세요. 앱 컨테이너의 `8765` 포트를 인터넷에 직접 공개하면 안 됩니다.

Dockerfile 기반 백엔드 앱 패널이 `PORT`와 앞단 Caddy를 제공하는 경우에는 [PLATFORM_DEPLOYMENT.md](PLATFORM_DEPLOYMENT.md)의 입력값을 사용하세요. 이 배포 방식은 `compose.yaml`을 사용하지 않습니다.

## “초보 추정 계정” 기준

계정 생성일 하나로 대상을 정하지 않습니다. 아래의 비민감 공개 메타데이터를 점수화하고, 기본 6점 이상인 저장소를 우선 검사합니다.

- 공개 저장소 수가 적음: 최대 3점
- 팔로워 수가 적음: 최대 2점
- 계정 활동 기간: 최대 2점이며, 신규 계정 여부는 필수 조건이 아님
- 저장소의 스타·포크가 없음: 각각 1점
- 저장소 크기가 2 MiB 이하: 1점
- 라이선스가 설정되지 않음: 1점
- 이름·설명·토픽이 학습/연습형 프로젝트를 나타냄: 2점

검색 자체는 최근 1~30일 안에 푸시된 스타 0~3개의 비포크 공개 저장소를 대상으로 합니다. 저장소 생성일은 제한하지 않습니다. 후보를 최대 검사 수의 3배까지 가져온 뒤 점수로 걸러 최대 1~25개를 검사합니다. 대시보드에는 각 탐지의 점수와 선정 신호도 표시됩니다.

이 점수는 사람의 실제 숙련도를 단정하지 않는 우선순위 휴리스틱입니다. 개인의 바이오·회사·위치 같은 프로필 내용은 사용하지 않습니다.

## 저장되는 정보

SQLite DB 기본 위치는 `.data/findings.db`입니다.

- 제공자, 탐지 패턴 이름, 신뢰도
- 저장소/소유자/파일 URL과 줄 번호
- 초보 추정 점수와 공개 메타데이터 기반 선정 신호
- 키가 `[REDACTED]`로 대체된 한 줄짜리 근거
- HMAC-SHA256 지문과 `••••••••끝4자리`
- 최초/최근 탐지 시각, 재탐지 횟수, 처리 상태

HMAC 키는 `.data/fingerprint.key`에 별도로 생성됩니다. 이 파일을 잃으면 기존 탐지와 새 탐지의 동일성 비교가 되지 않으므로 DB와 함께 보관하되 외부 공유는 피하세요.

## 의도적으로 하지 않는 것

- 실제 키 원문 저장·표시·내보내기
- 키 유효성 또는 잔액 확인
- 비공개 저장소 접근
- Git 커밋 이력 전체 탐색
- 자동 이슈·메일·DM 발송
- 무제한 병렬 수집 또는 배포

탐지는 오탐일 수 있습니다. 공개 링크와 마스킹된 근거를 사람이 검토한 뒤, 키를 메시지에 복사하지 말고 소유자에게 **폐기/재발급 및 Git 이력 정리**를 권하는 방식으로 연락하세요.

## 테스트

```powershell
python -m unittest discover -s tests -v
```

GitHub API는 검색 요청과 일반 REST 요청에 별도 제한을 적용합니다. Keylight는 작은 배치와 공개 아카이브 다운로드를 사용해 API 호출 수를 제한하고, 응답의 남은 요청 수를 대시보드에 표시합니다. 관련 동작은 [GitHub REST API rate limit 문서](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)에서 확인할 수 있습니다.
